*SHRINE Inspect is a local, read-only command-line tool. It measures your AI coding setup and session history against SHRINE and reports what to change first. It changes nothing itself.*

<Aside type="caution" title="Pre-release">
The install steps below apply once the maintainers publish the first release, `inspect-v0.1.0`, on the [releases page](https://github.com/stablekernel/SHRINE/releases). Until then, trial testers get the release files from a maintainer and follow [TRIAL.md](https://github.com/stablekernel/SHRINE/blob/main/inspect/TRIAL.md).
</Aside>

- The first release reads one harness: Claude Code; other harnesses come later
- It runs on your machine: macOS or Linux, with Node 20 or newer
- Source and full reference: [`inspect/`](https://github.com/stablekernel/SHRINE/tree/main/inspect) in the SHRINE repo

## What It Does

- Reads your setup: settings, instruction files, hooks, skills, agents, commands, plugins, and memory files
- With your consent, reads your local session history and the git log of the projects in it
- Checks both against SHRINE's principles, patterns, stack pages, and [anti-patterns index](/SHRINE/reference/anti-patterns/)
- Writes a report, plus a share-safe copy: what works for you, where there is room to amplify, and one change to start with

## What It Never Does

- Write to your project, your settings, or your history; its only writes go to its own folder
- Send anything off your machine at T0: no network, no model calls
- Send anything to SHRINE, Stable Kernel, or any telemetry service
- Call a model without your typed `yes` at Gate B
- Answer a gate for you; the skill never answers one

At T1 only, 12 scrubbed episode excerpts go to your model provider through your own coding agent login, one call each.

It checks that it changed nothing it read. If anything changed, the report shows a warning at the top.

## Install

<Steps>

1. Check the prerequisites: macOS or Linux, Claude Code, and Node 20 or newer (`node --version`)

2. Download the three release files into one folder: `shrine-inspect-<version>.tgz`, `install.sh`, and `SHA256SUMS`

3. Verify them: `shasum -a 256 -c SHA256SUMS` (Linux: `sha256sum -c SHA256SUMS`); every line must say `OK`

4. Install: `sh install.sh --skill`
   - It checks Node, then checks the tarball against the hash pinned in `install.sh`; a mismatch installs nothing
   - The CLI goes to `~/.local/share/shrine-inspect/<version>/`, linked as `~/.local/bin/shrine-inspect`
   - `--skill` also copies the Claude Code skill; leave it out to use the CLI only

5. Check: `shrine-inspect version`

</Steps>

## Run

- In your terminal: `shrine-inspect run --tier T0`
- Or ask your coding agent to run SHRINE Inspect; the skill starts a background run and tells you what to type
- Long runs: `shrine-inspect start --tier T1`, then `shrine-inspect status`; `status` prints the exact `approve` line for each gate
- Add `--background` to an `approve` command, and the run continues after you close the terminal

## Gates

The run stops at a gate when it needs your answer. Only you answer, in your own terminal.

| Gate | When | Your answer |
| --- | --- | --- |
| A | Before any session history is read | `history` to read it, or `no-history` for setup only |
| B | T1 runs only, after the scan | Keep T0, or type `yes` for T1 after reading its token and time estimate |
| C | Only when T1 judging passes a limit | Keep the partial results, or stop |

- Gate A lists the projects, date range, size on disk, and a time estimate
- Before Gate A, it reads file names, sizes, and dates, plus the first lines of the newest session per folder, and keeps only the folder, entry point, and version; no prompt text
- Never let an agent run `approve`: the CLI cannot tell you from a tool that fakes a terminal

## Tiers and Cost

| Tier | What it adds | Tokens | Time |
| --- | --- | --- | --- |
| T0 (scan) | Setup and history signals, no model calls | None | Minutes, by history size |
| T1 (Pulse) | 12 short episodes judged by your own coding agent login | About 54K measured on one run; Gate B shows the estimate first | Under a minute measured; Gate B shows the estimate |

- T1 tokens bill to your own account, like normal use
- Judging stops and asks (Gate C) past the approved token limit, past the time estimate plus 50%, at too many invalid answers, or at a usage limit
- Deeper tiers are planned, not in this release

## Scrubbing and Share-Safe File

- Before any text reaches a judge or a file, secrets are removed and names, paths, and hosts are masked
- `report.html` is for you
- `report.share-safe.html` masks names, paths, and hosts and drops session excerpts; share only this one
- Masking can over-mask: a word next to a path may become `<file>`

## Read the Report

- **Start with**: the one change to try first
- **Where you stand**: only the SHRINE areas that tripped, grouped Principles, Patterns, Stack
- **Findings**: each names its SHRINE page and what you gain, with a before and after example where one fits
- T1 findings are candidates, not facts: the judge's accuracy is not measured yet
- Every T1 finding shows N, the episodes, sessions, and repos behind it; a small N is a weak signal
- Pattern counts are appendix numbers only, never findings
- No score or grade, by design
- Apply a change in a normal session, under your own permission prompts, then run again to see it clear

## Remove

1. Wait for any run to finish (`shrine-inspect status`), then run `shrine-inspect purge`
2. Delete `~/.local/share/shrine-inspect`, `~/.local/bin/shrine-inspect`, and `~/.claude/skills/shrine-inspect`

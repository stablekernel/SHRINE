*SHRINE Inspect is a local, read-only command-line tool. It measures your AI coding setup and session history against SHRINE and reports what to change first. It changes nothing itself.*

<Aside type="caution" title="Pre-release">
This is a trial release. Get the newest `inspect-v*` release from the [releases page](https://github.com/stablekernel/SHRINE/releases). The steps below use `inspect-v0.1.3`. Trial testers also follow [TRIAL.md](https://github.com/stablekernel/SHRINE/blob/main/inspect/TRIAL.md).
</Aside>

- The first release reads one harness: Claude Code; other harnesses come later
- It runs on your machine: macOS or Linux, with Node 20 or newer
- Source and full reference: [`inspect/`](https://github.com/stablekernel/SHRINE/tree/main/inspect) in the SHRINE repo

## What It Does

- Reads your setup: settings, instruction files, hooks, skills, agents, commands, plugins, and memory files
- With your consent, reads your local session history and the git log of the projects in it
- Checks both against SHRINE's principles, patterns, stack pages, and [anti-patterns index](/SHRINE/reference/anti-patterns/)
- Writes a report, plus a share-safe copy: what works for you, where there is room to amplify, and one change to start with

## What It Never Does

- Write to your project, your settings, or your history; its own files go only to its own folder
  - At T1, each judge call launches Claude Code, which may update its own state and cache files (`~/.claude.json`, files under `~/.claude/`)
  - The installer is separate: it writes the CLI under `~/.local/` and, with `--skill`, the skill to `~/.claude/skills/shrine-inspect/`
- Send anything off your machine at T0: no network, no model calls
- Send anything to SHRINE, Stable Kernel, or any telemetry service
- Call a model without your typed `yes` at Gate B
- Answer a gate for you; the skill never answers one

At T1 only, 12 scrubbed episode excerpts go to your model provider through your own coding agent login, one call each.

- Each excerpt holds your messages, the start of each reply, the end of the last reply, and how the episode ended
- Code adds end signals: an open question for you in the last reply, a later revert or fixup, a later episode on the same files within a day
- Code searches all your loaded instruction files and sends only the lines that match your corrections
- When no line matches, that search counts as evidence; "could not tell" is kept for files that may have changed since or could not be read in full

It checks that it changed nothing it read. If anything changed, the report shows a warning at the top.

## Install

<Steps>

1. Check the prerequisites: macOS or Linux, Claude Code, and Node 20 or newer

   ```sh
   node --version
   ```

2. Download the three release files into a new folder

   ```sh
   mkdir -p ~/shrine-inspect-0.1.3 && cd ~/shrine-inspect-0.1.3
   base=https://github.com/stablekernel/SHRINE/releases/download/inspect-v0.1.3
   curl -fLO "$base/shrine-inspect-0.1.3.tgz"
   curl -fLO "$base/install.sh"
   curl -fLO "$base/SHA256SUMS"
   ```

3. Verify them; every line must say `OK` (Linux: `sha256sum -c SHA256SUMS`)

   ```sh
   shasum -a 256 -c SHA256SUMS
   ```

4. Install from the folder that holds the files

   ```sh
   sh install.sh --skill
   ```

   - Usage: `sh install.sh [--skill] [path/to/tgz]`; with no path, it uses the tarball next to `install.sh`, not in your current folder
   - It checks Node, then checks the tarball against the hash pinned in `install.sh`; a mismatch installs nothing
   - The CLI goes to `~/.local/share/shrine-inspect/<version>/`, linked as `~/.local/bin/shrine-inspect`
   - The installer is separate from the tool: with `--skill`, it copies the skill to `~/.claude/skills/shrine-inspect/`; leave it out to use the CLI only

5. Put `~/.local/bin` on your PATH, if the installer said so; add the line to `~/.zshrc` or `~/.bashrc` to keep it

   ```sh
   export PATH="$HOME/.local/bin:$PATH"
   ```

6. Check the install; `shrine-inspect --help` lists every command

   ```sh
   shrine-inspect version
   ```

</Steps>

## Run

- First run, scan only; it asks at Gate A whether to read your session history (type `history` or `no-history`)

  ```sh
  shrine-inspect run --tier T0
  ```

- Skip that question and read setup only

  ```sh
  shrine-inspect run --tier T0 --no-history
  ```

- T1 run: type `history` at Gate A, then `yes` at Gate B after reading its estimate

  ```sh
  shrine-inspect run --tier T1
  ```

- Long runs in the background; `status` prints the exact `approve` line for each gate, and the report paths when done

  ```sh
  shrine-inspect start --tier T1
  shrine-inspect status
  ```

- Add `--background` to an `approve` command, and the run continues after you close the terminal
- Or ask your coding agent to run SHRINE Inspect; the skill starts a background run and tells you what to type

## Gates

The run stops at a gate when it needs your answer. Only you answer, in your own terminal.

| Gate | When | Your answer |
| --- | --- | --- |
| A | Before any session history is read | `history` to read it, or `no-history` for setup only |
| B | T1 runs only, after the scan | Keep T0, or type `yes` for T1 after reading its token and time estimate |
| C | Only when T1 judging passes a limit | Keep the partial results, or stop |

- Gate A lists the projects, session files with the dates they last changed, size on disk, and a time estimate
- Gate B dates are when the sampled episodes started, so they can be earlier than Gate A dates
- The report counts sessions, not files; its appendix says why some files are not sessions
- Before Gate A, it reads file names, sizes, and dates, plus the first lines of the newest session per folder, and keeps only the folder, entry point, and version; no prompt text
- Never let an agent run `approve`: the CLI cannot tell you from a tool that fakes a terminal

## Tiers and Cost

| Tier | What it adds | Tokens | Time |
| --- | --- | --- | --- |
| T0 (scan) | Setup and history signals, no model calls | None | Minutes, by history size |
| T1 (Pulse) | 12 short episodes judged by your own coding agent login | Tens of thousands; Gate B shows the estimate for your run before anything is sent | Gate B shows the judging minutes; real time varies by machine, login, and network |

- T1 tokens bill to your own account, like normal use
- The judging time limit, the estimate plus 50%, is the only fixed time figure
- Judging stops and asks (Gate C) past the approved token limit, past that time limit, at too many invalid answers, or at a usage limit
- Deeper tiers are planned, not in this release

## Scrubbing and Share-Safe File

- Before any session text reaches a judge, secrets are removed and names, paths, and hosts are masked; the packs saved for judging (`workorder.json`) hold only that masked text
- `report.html` is for you; it is not masked and can show your names, paths, and hosts
- `report.share-safe.html` masks names, paths, and hosts and drops session excerpts; share only this one
- Masking can over-mask: a word next to a path may become `<file>`
- Before you share, check the copy against your machine; read-only, no network, exit 5 if it finds a name, path, or excerpt

  ```sh
  shrine-inspect check-share
  ```

- Reports land in the run folder: `~/Library/Application Support/shrine-inspect/runs/` (macOS) or `~/.local/state/shrine-inspect/runs/` (Linux)

## Read the Report

- **Start with**: the one change to try first
- **Where you stand**: only the SHRINE areas that tripped, grouped Principles, Patterns, Stack
- **Findings**: each names its SHRINE page and what you gain, with a before and after example where one fits
- T1 findings are candidates, not facts: the judge's accuracy is not measured yet
- Every T1 finding shows N, the episodes, sessions, and repos behind it; a small N is a weak signal
- Pattern counts are appendix numbers only, never findings
- No score or grade, by design
- Apply a change in a normal session, under your own permission prompts, then run again to see it clear

## Remove

1. Wait for any run to finish, then delete inspect's own folder

   ```sh
   shrine-inspect status
   shrine-inspect purge
   ```

2. Delete the install, the link, and the skill

   ```sh
   rm -rf ~/.local/share/shrine-inspect ~/.local/bin/shrine-inspect ~/.claude/skills/shrine-inspect
   ```

title: "Authority Cascade"
description: "Who decides what, and when personal preference applies."
---

*Not everything is up for debate. Know which layer owns the decision.*

## The Hierarchy

Decisions cascade through layers. Higher layers constrain lower ones.

1. **Organization**: Standards that apply everywhere
2. **Client**: Requirements that override org defaults for this engagement
3. **Team**: Conventions the team has adopted
4. **Role**: Expectations for this function (architect, engineer, reviewer)
5. **Individual**: Personal preference for everything not specified above

## How It Works

- Higher layers set constraints; lower layers fill in the gaps
- Client requirements override org standards where they conflict
- Personal preference applies only where nothing above objects
- When in doubt, escalate to the appropriate layer

## Why It Matters

- Prevents endless debates about solved problems
- Makes onboarding faster (standards are documented, not tribal)
- Enables staffing flexibility (anyone can work on anything)
- Reduces token waste (agents inherit context, don't rediscover it)

## Applying to AI Workflows

- **Org level**: Model routing policies, security constraints, cost controls
- **Client level**: Data residency, compliance requirements, approved vendors
- **Team level**: Preferred patterns, skill libraries, review standards
- **Role level**: What an architect vs. implementer decides
- **Individual level**: Harness choice, personal shortcuts, style preferences

## Anti-patterns

- Treating everything as personal preference
- Org standards that micromanage individual workflow
- No documentation of which layer owns what
- Relitigating decisions at the wrong layer
